# Settings 一致性整改 · 2026-09-09

本轮接续 SETTINGS-2026-09-08-FRAMEWORK、提供商管理及控件复用记录，按用户九张截图与十二项整改要求实施。Agent 预设的内容设计暂不调整。开始时工作区已有上一轮修改，本轮保留这些变更，没有提交、重置或清理工作区。

## 用户可见变化

- 删除设置分类搜索及分类标题下的通用副标题，保留字段用途说明。添加提供商目录仍保留搜索，方便查找完整服务目录。
- 保存操作统一放在标题右侧。无草稿只显示红色重置设置；有草稿显示保存、取消和状态。重置有二次确认，确认后暂存当前分类的默认值，再显式保存。保存和放弃更改都留在设置界面。
- 模型列表将配置状态、模型数留在信息侧，操作按钮只显示管理或配置。增加默认推理强度；选项来自官方模型元数据，切换默认模型会清除旧模型的 effort 覆盖。
- 管理页和添加自定义提供商共用 Orbs 表单，管理页使用独立标题与全宽内容布局，复用 Settings 主题和控件，不再显示一级分类侧栏。删除高级设置入口，删除模型提供商取代断开连接；按钮不再使用方括号。
- 管理页 Tab 在表单与全局操作间切换，Ctrl+S 可直接保存已确认的字段草稿。连接测试是独立操作，执行中可按 Esc 取消。
- 表单标签与控件宽度不因焦点改变而移动；按钮预留固定一个字符的选中标记。测试连接复用 Orbs Orb 和既有 MotionHost，成功、失败、取消或离开页面时释放动画。
- 插件常见字段根据真实用途显示一句话描述，优先沿用 schema 自带说明；移除统一的保存/恢复默认废话。

## 状态和持久化边界

普通设置、默认模型、默认 effort 和提供商名称/地址共享同一草稿事务。预览不写文档；取消不写；重复选择同值不触发写入。批量草稿保留该 namespace 首次编辑的 revision，外部写入产生冲突时保留草稿并提示重新编辑，不静默覆盖。

保存进行中不接收第二次提交，退出协调器会等待已经提交的设置写入完成。失败仍留在 Settings，草稿可重试。已保存配置由官方 Settings 服务持久化。未点击保存的草稿仍仅在内存，强制杀进程或断电不会自动提交，也不在磁盘另存明文密钥。

授权、删除提供商、添加提供商及添加模型 ID 是显式独立操作：调用既有官方服务，分别保留确认/取消与进行中保护。删除移除可写的本地连接、用户提供商配置和凭据；部署管理的基础配置不伪装成可删除。测试连接不创建 Session、不修改设置文档。

## 实现与自审

- page-machine 负责草稿、版本及保存/取消状态；projectSettingsDrafts 只投影非密钥标量，stageSettingsMutation 拒绝未支持字段，避免绕过全局保存直接写盘。
- providers-controller 负责提供商服务状态、模型元数据、授权和测试生命周期；frame 只投影展示数据。默认模型和 effort 不另建一套持久化机制。
- SettingsWorkspace 负责布局、控件和动画，terminal driver 提供共享 MotionHost。保留编辑值、选中状态与显示信息的边界，去掉已失去入口的管理分支。
- 逐个复核返回链：选择器取消回原页，管理返回模型列表，保存/放弃保持设置，确认弹窗默认取消，执行中重复输入不产生重复请求。
