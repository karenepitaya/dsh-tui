# Settings 模型与服务：提供商管理设计

状态：已根据用户确认的“动态供应商列表、配置浮窗、测试按钮”完成实现并安装；验证与安装记录见 [本轮交付](SETTINGS-PROVIDERS-2026-09-08-RESULT.md)。

## 要解决的事

用户需要添加一个模型服务、填写凭据、选择模型，以及以后修改这些信息。当前页面递归展开 `providers` 的 schema，把协议兼容标志和普通设置混在一起，却没有创建提供商的入口。此次调整仅涉及 Settings 的“模型与服务”，保留现有 pi-tui + Orbs、共享主题、主页面字号、键盘导航和 q 的输入上下文规则。

## 页面结构

1. **模型与服务首页**：页头右侧固定显示“＋ 添加提供商”；内容仅保留“新会话默认模型”和提供商列表。每行显示名称、凭据状态、模型数量与“管理”入口；异常或未完成配置提供“继续配置”。列出已配置记录，完整内置服务目录放在添加流程。列表状态没有草稿，不显示“所有更改已保存 / 保存更改 / 恢复默认”操作栏。
2. **提供商配置浮窗**：选中服务后打开居中浮窗，背景保留模型首页。浮窗提供凭据、测试模型、测试连接、名称和地址等操作；列表可滚动，确认与返回提示固定可见。自定义服务可以添加模型 ID。高级设置、断开凭据和移除用户配置保留独立入口。不增加常驻第三栏。
3. **添加提供商**：先搜索并选择内置服务，或进入“自定义兼容服务”。内置服务使用官方公布的登录方法或 API key 流程，不重复询问协议与地址。自定义服务选定类型后，只需名称、地址、密钥、至少一个模型 ID；本地服务需要无密钥连接时明确选择其支持的方式。
4. **高级设置**：从当前提供商详情进入，并能通过现有高级入口访问。按“协议兼容、模型能力、请求参数”分组。`supportsStore`、`supportsDeveloperRole`、`supportsReasoningEffort`、`maxTokensField`、`requiresToolResultName`、容量、超时、重试、headers 等不出现在首页或基本信息中。没有显式覆盖的可选值显示“使用默认”，不能把未知值画成“关闭”。

## 添加与编辑行为

- 内置流程：添加 → 选择服务 → 登录或输入密钥 → 返回列表并定位新记录。服务名称与登录方法来自运行时目录，不在 TUI 写死品牌列表。
- 自定义流程：选择兼容类型 → 填写小表单 → 添加 → 返回列表。类型确定默认协议；精细协议覆盖归入高级。名称和地址使用清楚的字段提示，模型 ID 只解释“填写服务商提供的模型名称”。不重复附加同一句保存说明。
- 输入错误留在当前字段，保留已经输入的非秘密内容。取消不创建配置。开始提交后若仅配置注册成功、凭据保存失败，显示“已添加，待配置凭据”，可继续完成，不误报全部成功。
- 凭据只走官方凭据服务。详情不显示密钥原文、环境变量名或凭据服务内部信息；更换凭据使用掩码输入。
- 保存基本信息后原位反馈；只有存在编辑草稿时显示保存/取消。q/Esc 在子页面返回上一层，有未保存修改时确认放弃；在输入中 q 保持普通字符。
- 默认模型标明“仅影响新建会话”，不会顺带切换当前会话模型。更换默认模型同时移除旧模型的推理强度覆盖，使用新模型默认值；模型与推理强度不做组合选项列表。
- “已配置凭据”表示凭据存在，不能显示成“测试通过”。只有点击“测试连接”或按 t 才发送一次固定的 `Reply with OK.` 请求；没有工具、项目内容或历史会话，也不创建 Session。显示结果与耗时，支持取消和超时；输出额度不足与完整响应分别反馈。界面提示可能产生少量费用。
- 断开凭据不会自动等同于删除地址和模型。移除用户配置需要说明影响；存在系统/部署继承值时，明确提示恢复继承值，不承诺永久删除。

## 空状态与布局

- 无提供商：一句“添加模型服务后即可选择模型”，紧邻“＋ 添加提供商”，不展示空表单或无意义只读项。
- 加载、加载失败、设置不可写均在当前区域说明原因；失败保留重试，受部署管理的项目标明可操作边界。
- 宽屏保留 Settings 侧栏，内容使用剩余宽度。提供商列表是完整的一行记录，不再按每个提供商展开大表单，也不新增空的常驻详情栏。
- 窄屏继续顶部分类，目录与配置浮窗使用当前可用宽高并滚动内容，操作提示始终可见。沿用 Orbs 的真实组件与共享主题。
- 保持共享蓝灰主题、统一终端字体大小。颜色只表达焦点和状态；选中、只读与待配置仍有文字或符号，不依赖颜色识别。

## 实现依据与边界

- `src/settings/page-catalog.ts` 当前递归展开 provider 对象，`models` 等集合只读；需要在 models 分类按提供商对象投影，不能只删除几行标签。
- `src/provider/port.ts` / `src/dsh/provider-connection.ts` 提供动态目录、认证连接、断开与脱敏元数据。`SettingsProvidersController` 管理浮窗状态，复用同一官方认证端口；`src/dsh/provider-test.ts` 通过官方 `resolveModelInfo → prepareCall → stream` 执行隔离测试。
- 新建自定义服务可通过 `SettingsCatalogPort.mutateSettings` 注册 `llm-pi-ai.providers.<id>`，再复用凭据连接。两者非原子，必须处理部分完成；新增不能覆盖已有记录，保存保留 revision 冲突检查。
- 本地官方 rc.2 的 `deepseek-harness/packages/llm/llm-pi-ai/src/catalog.ts` 确认：自定义服务需要协议、地址和至少一个非空且不重复的模型 ID；模型名称、容量、token 上限可省略。服务目录并非自动网络探测，默认容量不应被宣传为实测值。
- `src/dsh/provider-connection.ts` 的 `connected` 是 active 与凭据配置状态组合，并不进行远程可用性验证。
- `src/dsh/model-selection.ts` 的 `selectModel(..., {saveDefault:true})` 会先修改当前 Agent；本页修改“新会话默认模型”应走 `agent-default-model` 的 Settings 写入，避开这个副作用。

## 验收标准

1. 进入模型与服务即可识别已有提供商、默认模型和添加入口；首页没有 `supports*` 等兼容字段。
2. 内置服务能通过现有认证流程配置；自定义服务能在 TUI 中完成创建与模型 ID 填写，无需手改配置文件。
3. 从详情直接更换凭据或编辑基本信息；高级设置始终保留，隐藏不是删除能力。
4. 取消无写入、部分失败可继续、冲突不覆盖、秘密不回显；仅修改新会话默认值时当前会话模型不变。
5. 空列表、长服务名、多提供商、只读、窄屏、单色及 q 行为通过实际组件和 ConPTY 验收，再打包安装。
6. 浏览目录不发送模型请求；点击测试恰好发送一次固定请求，设置与 Session 文件不变化。迟到的结果、取消和关闭不会污染重新打开的浮窗。

开发验证使用内存适配器和隔离的本地 mock 服务；真实 profile 仅用于安装恢复材料的备份与字节核对，不输出配置内容。
