# 2026-09-07 产品交互与组件依赖审计

本轮基线：main 上的 ba7852f。用户授权同时审计 DSH-TUI 产品交互与 pi-tui-orbs 依赖可复现性，并直接修复。范围包括截图中的审批、Sessions、Models、Modes、MCP、Skills、Settings，以及主聊天草稿恢复、公共页面导航和隔离安装。

## 判断与取舍

多个页面直接把运行时字段当作界面：UUID、原始参数、资源状态和配置层级排在用途和操作前面。功能存在、投影可渲染、覆盖率达到门槛，都不能证明用户能理解或完成任务。本轮按“当前是什么、可以做什么、执行会影响哪里”重排内容，完整诊断信息保留在显式详情与官方审计记录中。

- 审批说明、会话授权、模型去重、Session 标题、空页面、默认详情、菜单去重和草稿串稿均先用实际失败的回归证明问题，再修改实现。

## 保留边界

- 会话内授权是当前连接内、指定工具与目录及权限范围内的记忆，不是命令前缀白名单，也不是永久权限修改。
- 旧 Session 的标题不存在时不调用模型猜测，不删除看起来像测试数据的历史会话。
- 非 Shell 工具仍使用通用参数视图，尚未为每一种工具提供专用的文件内容或差异预览；完整参数可以查看，不把通用参数视图称为专用审批设计。
- 任意扩展的复杂配置仍需要显式查看字段/值；不假装已为未知第三方配置提供专用表单。
- 官方 E2E 仍需要文档注明的 Harness 源码；普通开发/构建不再需要相邻 Orbs 仓库。
- 无锁消费者选择新的上游 Cordis include 版本时会出现 peer 警告，已记录在 green-3 的 peerDependencyAudit；真实 profile 安装也报告 peer warning，本轮未逐项追查该 profile 的全部冲突，不升级受约束的官方依赖。源码 clone 复现使用根锁文件，不把无锁下游解释为严格兼容性证明。
- Legacy Chat 与部分兼容页面的架构迁移仍在进行；本轮没有以产品修复为名整体替换底层框架，也不声称已经找完所有 bug。
